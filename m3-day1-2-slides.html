Vibe Coding คืออะไร

บอก AI ว่าอยากได้อะไรเป็นภาษาคน ให้ AI เขียนโค้ด แล้วเราคุมทิศทางและตรวจผล

คำนี้ Andrej Karpathy ใช้ต้นปี 2025 จนกลายเป็นคำเรียกวิธีทำงานแบบนี้ ในคอร์สนี้เราใช้แบบ “มีวินัย” คือไม่เชื่อโค้ดจนกว่าจะตรวจ

วงจรที่เราจะใช้ทุกคาบ

Promptบอกบริบท ข้อมูล งาน และข้อกำหนด
→
Runรันจริง ดูผลบนหน้าจอ อ่าน error
→
Verifyเทียบตัวเลขกับต้นทาง คำนวณมือ 2–3 จุด
→
Refineบอกสิ่งที่ผิดให้ชัด แล้วสั่งแก้

↺ วนจนตัวเลขถูกและหน้าตาใช้งานได้

ขั้นที่คนข้ามบ่อยที่สุดคือ Verify และเป็นขั้นที่สำคัญที่สุดในงานข้อมูล กราฟสวยแต่ตัวเลขผิดอันตรายกว่าไม่มีกราฟ

จุดแข็งและกับดัก

AI ช่วยได้มาก

  • ตั้งโปรเจกต์และเขียนโค้ดซ้ำ ๆ ในไม่กี่นาที
  • ลองไอเดียได้เร็ว ทิ้งได้ไม่เสียดาย
  • อธิบายโค้ดและ error เป็นภาษาไทย
  • คนที่ไม่ใช่โปรแกรมเมอร์สร้างเครื่องมือเองได้

ต้องระวัง

  • มั่นใจแต่ผิด โดยเฉพาะตัวเลขและสูตร
  • แก้จุดหนึ่ง พังอีกจุดโดยไม่บอก
  • โค้ดยาวขึ้นเรื่อย ๆ จนไม่มีใครเข้าใจ
  • ใส่ API key หรือข้อมูลลับลงโค้ด

เครื่องมือ 2 แบบ

สร้างแอปจาก prompt

v0, Lovable, Bolt

  • เร็วมาก เห็นผลบนเว็บทันที
  • เหมาะกับต้นแบบ ทดลองหน้าตา
  • ควบคุมโครงสร้างโค้ดได้น้อย

AI ในโปรแกรมเขียนโค้ด

Cursor, Claude Code, Copilot

  • ทำงานในโปรเจกต์จริงบนเครื่องเรา
  • เหมาะกับงานที่ต้องดูแลต่อยาว ๆ
  • เป็นแบบหลักของคอร์สนี้

ส่วนสีเหลืองคือส่วนที่คนมักลืม และเป็นต้นเหตุของตัวเลขผิดเกือบทั้งหมด

ถ้าได้ตัวเลขนี้แปลว่าสั่ง AI แก้ว่า

Verify: เทียบกับ Pivot Table

  1. เปิด sales.csv ใน Excel หรือ Google Sheets
  2. เพิ่มคอลัมน์ revenue = qty * unit_price
  3. Insert → Pivot Table: Rows = branch, Values = SUM of revenue
  4. เทียบกับกราฟแท่งใน Dashboard
  5. แคปหน้าจอทั้งสองฝั่งเก็บไว้เป็นหลักฐาน

Data profiling ด้วย AI ใน Google Colab

ช่วยทำ data profiling ของ DataFrame df (จาก sales_raw.csv) ด้วย pandas:
- จำนวน null และค่าไม่ซ้ำของแต่ละคอลัมน์
- หาแถวที่ซ้ำกันทุกคอลัมน์
- ตรวจคอลัมน์ datetime ว่ามีปี พ.ศ. หรือรูปแบบวันที่อื่นปนอยู่หรือไม่
- แสดงชื่อสาขาทั้งหมดพร้อมจำนวนแถว
- หาแถวที่ unit_price ไม่ใช่ตัวเลข หรือติดลบ หรือ qty = 0
อย่าแก้ข้อมูลก่อน ให้รายงานปัญหาที่พบเป็นตารางก่อน

Firestore กับ Supabase

NoSQL (เอกสาร)

Firebase Firestore

  • เก็บเป็นเอกสาร JSON
  • real-time ง่ายมาก
  • มี login, hosting ในที่เดียว
  • สรุปข้อมูลซับซ้อนทำยากกว่า

ใช้เป็นหลักในคอร์ส

SQL (ตาราง)

Supabase (PostgreSQL)

  • เก็บเป็นตาราง เหมือน Excel
  • ใช้ SQL สรุปข้อมูลได้ทรงพลัง
  • มี real-time และ login เช่นกัน
  • เหมาะกับงานวิเคราะห์หนัก ๆ

ทางเลือกสำหรับคนที่รู้ SQL

โครงสร้าง Firestore

collection คือกลุ่มของเอกสาร เหมือนชีต
document คือ 1 รายการ เหมือน 1 แถว
field คือค่าในเอกสาร เหมือนคอลัมน์

ออกแบบให้ query ง่าย: เก็บ date เป็นข้อความ “2026-09-20” และคำนวณ revenue ไว้เลย จะกรองและรวมได้ทันที

อ่านข้อมูล 2 แบบ

getDocs · อ่านครั้งเดียว

เหมือนถ่ายรูป ได้ข้อมูล ณ ตอนนั้น ข้อมูลเปลี่ยนต้องกดโหลดใหม่

onSnapshot · ฟังตลอดเวลา

เหมือนดูไลฟ์ ข้อมูลเปลี่ยนเมื่อไร หน้าจออัปเดตเอง

useEffect(() => {
  const q = query(collection(db, "sales"), where("date", ">=", startDate), orderBy("date"));
  const unsub = onSnapshot(q, (snap) =>
    setRows(snap.docs.map((d) => ({ id: d.id, ...d.data() }))));
  return () => unsub();   // เลิกฟังเมื่อออกจากหน้า ไม่งั้นจะอ่านซ้ำเรื่อย ๆ
}, [startDate]);

Security Rules: ใครทำอะไรได้บ้าง

โหมดทดสอบ (อันตราย)

allow read, write: if true;

ใครก็ได้บนโลกอ่าน แก้ และลบข้อมูลทั้งหมด

อย่างน้อยต้องเป็นแบบนี้

match /sales/{id} {
  allow read: if request.auth != null;
  allow create: if request.auth != null
    && request.resource.data.qty > 0;
  allow update, delete: if false;
}

ต้องล็อกอินจึงอ่านได้ · เพิ่มได้แต่ qty ต้องมากกว่า 0 · แก้และลบไม่ได้เลยจากหน้าเว็บ
